## The tab (binding unless you find a concrete reason; say so if you depart)

Root `Ui.withResultBar`; the last answer is kept in fields and shown again after a rebuild. One column, cards:

1. "Now using": a chip from the phone's own label (5G UW / 5G / 4G; grey before a scan; amber when the phone does not
   answer), facts Network, Carriers, Signal (dBm of the 4G cell), the per-carrier lines, one primary button "Scan"
   (`GET /cells`). The raw cell list goes into the result strip's Details. The tab scans by itself when it is shown (not
   while a comparison runs, not when the last scan is under a minute old) and once about 8 s after a mode switch or the end
   of a comparison. No timer otherwise.
2. "4G or 5G": a chip for the present mode (`net_get`), a `Ui.Choice` "5G allowed | 4G only" (`net_5g` / `net_lte`; off
   while a comparison runs; a hint that 4G only also saves the phone's battery, and that 5G was faster in the evening
   measurement: 11.0 against 6.5 Mbit/s upload). Divider. "Compare the two": a two-line hint (several rounds in random
   order, the phone is put back, about 5 minutes for 5 rounds, uses mobile data), `Ui.Choice` "3 | 5 | 7" rounds, "Start"
   (primary) and "Stop", a progress line, the table in `Ui.mono`, and after a run "Keep: <the better one>" only when a
   setting is recommended. D8: the words after Keep say when it ends: until you switch back, press Restore everything, or
   mobile data is down for some minutes (then the phone puts 5G back by itself).
3. "Best spot for the phone": a two-line hint (carry the phone around; the tablet beeps higher where the signal is
   better), "Start" / "Stop", a `Ui.Toggle` "Beep", the score line large, two mono lines, "Best so far", a name field with
   "Mark", the list with the best starred. It asks `/sig` only while started AND shown. The old hint "The phone must stay
   on the hotspot" is false (`/sig` is served over Bluetooth too): drop it.
4. "Tools": quiet buttons, one line each: "Search for a network again" (asks first: the hotspot drops for some seconds;
   `radio_cycle` with a long wait, then asks `radio_cycle_state` every 3 s until it says done, then scans, and shows the
   bands before and after; D6), "Phone info screen" (asks first, with the warning from HANDOFF about the switches not to
   touch on that screen; sends `menu_open` with `com.android.phone/.settings.RadioInfo` and, if the answer does not start
   with "Opened", `com.android.settings/.RadioInfo` (D5); then offers the Screen tab to look at it), "Safety check",
   "Restore everything" (the same code the Phone tab uses: one implementation).

## Behaviour

- A comparison keeps running when the tab is hidden (by design: it is finite and puts the phone back); its progress is
  shown again when the tab is shown. Everything else stops when the tab is hidden.
- Nothing that changes the phone can be sent twice by a double tap. No blocking work on the main thread.
- Over Bluetooth: scanning, the mode switch and the tools work (`/act`, `/cells`, `/sig`); the comparison needs the
  hotspot (it measures the hotspot's speed): say so instead of starting.
- The NEW tablet against an OLD phone sends only names an old phone knows (`/cells`, `/sig`, `/speed/*`, `net_get`,
  `net_lte`, `net_5g`, `radio_cycle`, `radio_cycle_state`, `safety`, `restore`, `menu_open`). A missing answer shows "not
  known", never a guess.
- Every `/act` whose answer says `"later": true` is followed up (`FollowUp` where the status can show the outcome;
  `radio_cycle_state` for the search).
